# agent-memory

agent-memory 是一个自托管的记忆服务：AI agent 通过 MCP（HTTP）读写一处跨会话保留的长期记忆，人通过内置的 Web 界面查看、检索、整理和授权。

它记的是“这段时间在做什么”这类会过时、和具体项目或场景绑定的信息，由 agent 在日常工作中维护，而不是一份长期稳定的公共知识库。

单二进制、单文件 SQLite，管理界面直接嵌在二进制里；可选接入 embedding 与 reranker 提升检索质量。

## 快速开始

需要 Rust 1.85 或更新版本；构建完整管理界面还需要 Node.js 与 pnpm。

```bash
git clone https://github.com/Leawind/agent-memory.git
cd agent-memory
pnpm install && pnpm build   # 构建管理界面，产物会嵌入二进制
cargo install --path .
agent-memory serve
```

如果只用 MCP、不需要管理界面，可以跳过 `pnpm` 两步；此时服务嵌入的是占位页。

默认监听 `127.0.0.1:8899`，数据写入当前目录的 `memory.db`：

- 管理界面：<http://127.0.0.1:8899/>
- MCP 端点：<http://127.0.0.1:8899/mcp>

客户端配置示例（本地开放模式可以去掉 `headers`）：

```json
{
  "mcpServers": {
    "agent-memory": {
      "type": "http",
      "url": "http://127.0.0.1:8899/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

数据库路径和服务地址都走命令行参数：

```bash
agent-memory --db /srv/agent-memory/memory.db serve --host 0.0.0.0 --port 9000
```

服务启动时会把解析后的数据库路径打印到 stderr。没有配置文件：鉴权、模型、衰减策略、提示词等运行时设置存在数据库里，由管理界面维护。

## 基本概念

### 记忆

一条记忆由 id、摘要、可选正文、标签和时间组成。摘要是列表与搜索结果里看到的一行；正文是展开后才读的完整 Markdown。

读取采用渐进式披露：列表、搜索和资源目录只返回摘要与片段，只有按 id 读取单条才返回正文。这样 agent 可以先用少量上下文判断相关性，需要时再取全文。

id 形如 `m3`，但不稳定：删除或合并后失效，导出再导入会重新编号。因此正文里引用其他记忆时，用标签或关键词互链，不要写 id。

写入时如果已有摘要相同或语义相近的记忆，响应会给出查重提示，可以直接合并。

### 标签

标签是整个库共用的一套词汇表，没有独立的“键”和“值”两种类别。一条记忆上的标签处于三态之一：

- 裸标签，如 `rust`；
- 一条边的源端；
- 一条边的目标端。

`project:nmmt` 表示一条从 `project` 指向 `nmmt` 的边，键值对只是它的展示形式。目标端是词条引用：同一个 `nmmt` 可以被多个源端指向，改名或补充描述会作用到所有出现的地方。一条记忆内，一个标签最多作为一条边的源端，也不能同时是源端和目标端；同一个标签在不同记忆上可以扮演不同角色。

标签名由 Unicode 字母、数字、`_`、`-`、`.` 组成，长度 1–100 字符，以字母、数字或 `_` 开头；冒号只用于边的展示。`tag_list` 默认只列组织性标签（作过源端或裸用过），只被别的标签指向的词条需要显式过滤才出现；删除标签会移除它在所有角色上的标注。

### 标签表达式

`tag_expr` 用布尔表达式筛选记忆：

- `&` 与、`|` 或、`!` 非、括号分组；
- `key=value` 精确匹配一条边，数字按规范形式匹配（`key=1.0` 命中 `key:1`）；
- `/regex/` 按正则匹配任一标签展示形式；
- `@name` 引用命名谓词；
- `mutex(a, b, ...)` 表示至多一个为真。

例如 `project=nmmt & (rust | /^topic\./) & !archived`。

### 检索

`memory_search` 是默认的召回方式：空白分隔的词必须全部命中，引号内按短语精确匹配；可以先用 `tag_expr` 做硬过滤，再对结果排序。结果只包含摘要与片段。

服务端把内容关键词、标签匹配（以及配置后的语义相似度）分别排名，再用 RRF 融合。语义通道可选：没配置时自动只用关键词；配置后换说法、跨语言的查询也能召回；embedding 服务不可用时自动回退关键词并在响应里标明。配置 reranker 后还会对候选池重排，重排服务不可用时保留融合排序。

搜索响应带短期游标，翻页复用同一份快照；内容或设置的写入会使快照失效，游标过期后重新搜索即可。

### 时效与访问强化

记忆没有隐藏状态：没有置顶、归档或到期，删除是唯一的移除手段。

排序里有两条独立、可关闭的信号。时效衰减按有序的标签规则给不同记忆设置半衰期，默认不衰减；访问强化只统计成功的正文读取和显式 `memory_use`，列表、搜索曝光不算，同一身份 60 秒内的重复只算一次。两者都只调整相关结果的顺序，不扩大也不缩小召回范围。

### 命名谓词与约定

常用的标签组合可以固化成命名谓词，在 `tag_expr` 里用 `@name` 引用，也可以用于衰减规则。谓词定义随备份导出；写入需要独立的“管理谓词”能力，管理员权限不会隐式授予它。

保留标签 `convention` 用来存放长期约定。它不能被改名或删除，挂载和摘取需要管理员；带这个标签的记忆会作为常驻约定出现在资源目录里，agent 可以先读约定再开始工作。

### 资源

除工具外，记忆库还以 MCP 资源的形式暴露：

- `memory://tags/{tag}`：一个标签的目录，含标签元数据与最近更新的 100 条记忆摘要，不含正文；
- `memory://memories/{id}`：单条记忆的完整 Markdown 正文。

`resources/list` 会列出组织性标签和常驻约定（与 `tag_list` 的默认集合一致）。

## 功能

### 管理界面

浏览器打开服务地址即可使用工作台：左侧是标签侧栏（名称、描述、计数），右侧是记忆列表、搜索框和编辑器。可以新建、编辑、删除和合并记忆，Markdown 正文带预览，破坏性操作需要二次确认。

“管理”面板需要管理员权限，包含：

- 身份与访问：创建身份、勾选能力、重置 token 或删除身份、开启鉴权、配置匿名能力；
- 搜索模型：embedding 与 reranker 候选列表、逐一检测、补跑向量、候选预算；
- 时效与强化策略；
- 备份导入导出、数据体检；
- 自定义提示词：随 MCP 握手返回给 agent，可替换内置默认，用来放你的长期规则。

### 身份与权限

没有账号体系，token 就是身份；服务端只存哈希，明文只在创建或重置时显示一次。能力分为：读取、新建记忆、修改记忆、删除记忆、管理标签、管理谓词、管理员。

默认是开放模式，服务也只监听本机：任何能连上本机的程序都能读写。对局域网或公网开放前，先按下面的步骤开启鉴权，并在前面放一层 HTTPS 反向代理（服务本身只提供 HTTP）。要给其他人或机器使用时：

1. 先在管理面板创建一个带“管理员”能力的身份，保存好它的 token；
2. 再打开 Token 鉴权开关；
3. 之后按需为每个使用者创建身份，逐项勾选能力。

鉴权开启后，`/mcp` 和 `/api` 都必须携带 `Authorization: Bearer <token>`。可以为无 token 的请求单独配置一组匿名能力（例如只读）；没有配置时无 token 一律 401，无效 token 也不会降级成匿名。丢失唯一的管理员 token 时，可以用 `agent-memory token reset` 重置最早创建的管理员身份。

### 备份、迁移与体检

全部数据在一个 SQLite 文件里。停止服务后复制这个文件，就能把整个库搬到另一台机器；运行中的 WAL 文件不要单独拷。

也可以导出为 JSON 备份，再导入空库恢复。导出不会覆盖已有文件；导入只接受空数据库，是恢复而不是合并。JSON 备份只包含记忆、标签、谓词、时效策略和访问统计；身份、鉴权开关与模型配置不在里面，需要在新机器上重新配置。向量是派生数据，同样不在备份里，恢复后跑一次 `embed-backfill` 补齐。

`doctor` 检查数据库完整性、引用一致性、标签大小写冲突、空摘要、重复记忆和向量覆盖等问题，发现问题时退出码为 1。

### 语义搜索与重排

在“管理 → 搜索模型”里添加 OpenAI 兼容的 `/embeddings` 候选；列表顺序就是故障切换顺序，运行时按顺序实际调用，失败自动切到下一个。

| 部署                      | base_url                        | model               | API Key |
| ------------------------- | ------------------------------- | ------------------- | ------- |
| SiliconFlow（国内直连）   | `https://api.siliconflow.cn/v1` | `BAAI/bge-m3`       | 必填    |
| 本地 Ollama（数据不出机） | `http://127.0.0.1:11434/v1`     | `bge-m3`            | 留空    |
| 其他 OpenAI 兼容服务      | 各家端点                        | 对应 embedding 模型 | 按需    |

可以为每个候选单独设置查询/文档指令前缀和余弦下限；前缀或模型变化会使旧向量失效，需要补跑。重排候选使用 Cohere 风格的 `/rerank` 端点（本地可用 Xinference、TEI、llama.cpp 等），同样按列表顺序故障切换。

配置后，搜索自动融合语义通道；服务不可用时只降级不失败：搜索退回关键词并显式标记，写入不阻塞，缺的向量可以随时补跑。

## 命令行

所有子命令共用全局参数 `--db <PATH>`：

| 命令                 | 作用                                           |
| -------------------- | ---------------------------------------------- |
| `serve`              | 启动 HTTP 服务（默认子命令）                   |
| `stats`              | 打印记忆数、标签数、文件大小与向量覆盖         |
| `doctor`             | 数据体检，发现问题时退出码为 1                 |
| `export <FILE>`      | 导出 JSON 备份，拒绝覆盖已有文件               |
| `import <FILE>`      | 从备份恢复到空数据库                           |
| `embed-backfill`     | 为缺失向量的记忆补跑 embedding                 |
| `token reset [NAME]` | 重置身份 token；省略名字时重置最早创建的管理员 |

`agent-memory --help` 与各子命令的 `--help` 是参数的最终说明。
